# 定稿结果到代码的筛选清单

筛选依据：`00_使用清单_定稿结果表使用清单.md` 与 `00_来源说明.md`，口径为慢病主样本、2011-2018、堆叠 DID、8 控制、城市聚类。

## 筛选结论

- 直接使用：8 个脚本
- 部分使用（只取数据构建和附录表）：1 个脚本
- 不使用：2 个脚本
- 补检索到并放入 `04_待核对_诊断与样本`：2 个脚本（诊断表、样本流程）

## 二、部分使用的代码

### `RQ_stacked_v2.R`

只应取下面这些输出：

| 输出 | 使用位置 |
| --- | --- |
| `data_stacked_v2.csv` | 统一分析数据，所有估计脚本的输入 |
| `rq2_value_att_v2.csv` | 附录 RQ2 9 档取值 |
| `rq2_quintile_att_v2.csv` | 附录 RQ2 五分位 |
| `rq2_quintile_contrasts_v2.csv` | 附录 RQ2 五分位对比 |

不使用它生成的 `rq1_att_stacked_v2.csv` 与 `rq1_cohort_att_v2.csv`，它们是使用清单中明确排除的全样本/中间版。该脚本读取 `2026-08-07` 下的 `revised_data.csv` 与 `analysis_df_v2.csv`，如果只保留现有 `data_stacked_v2.csv` 而不做全流程复现，则不需要重跑它。

## 四、补检索到的缺失代码

这两个脚本已放入 `04_待核对_诊断与样本/`。

### 1. `rq2_diagnostics.py`

生成定稿清单中的 4 个诊断表：

| 输出 | 使用位置 |
| --- | --- |
| `rq2_diag_control_missing.csv` | 诊断/方法表 |
| `rq2_diag_sample_by_controls.csv` | 诊断/方法表 |
| `rq2_diag_gdp_balance.csv` | 基期平衡 |
| `rq2_diag_dvi1_support.csv` | DVI=1 支持度 |

注意：该脚本读取 `rq2_final_v1/rq2_final_data.csv`。旧数据中慢性主窗口为 17,844 行，与定稿 `data_stacked_v2.csv` 的 17,723 行不一致，因此四个诊断表投稿前需要按“慢病主样本 + 堆叠 DID + 8 控制”的新口径重跑，不能直接把现成 CSV 当定稿结果。

### 2. `RQ1_RQ2_unified.R`

只取其生成 `sample_flow.csv` 的部分，位于脚本第 140-160 行附近：

| 输出 | 使用位置 |
| --- | --- |
| `sample_flow.csv` | 样本流程（方法或附录） |

核对结果：

- `baseline_60plus_matched = 7,088`，与 `data_stacked_v2.csv` 基期行数一致；
- `chronic_main_window = 17,723`，与 `data_stacked_v2.csv` 中 `chronic_base == 1` 的 17,723 行一致；
- `chronic_baseline_persons = 5,299`，与定稿数据一致。

因此该 `sample_flow.csv` 的主要流失数字可以直接使用。注意该脚本整体仍是 2026-08-29 的旧 CS-DID 统一版本，只提取样本流程片段，不要运行它来生成 RQ1/RQ2 主表。
